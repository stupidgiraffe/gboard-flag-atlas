How to Use the GboardWu Flag Editor Without Guesswork

A practical workflow for looking up GboardWu flags, comparing types and defaults, recording changes, and reversing experiments.

What you should know

Search the exact name, inspect the actual editable type, and keep a before/after record before touching an experiment.

Evidence standard: these are real catalog identifiers, but their effects can be inferred, version-specific, or gated. Check the confidence and APK notes before changing settings.

Find the right editor

In a supported GboardWu patch build, look for Patches → More settings → Developer options → Flag Editor. The exact menus may vary by patch version. A normal stock Gboard installation does not expose this workflow. The Atlas is a reference: clicking Copy name copies an identifier; it does not silently change your keyboard.

Don't assume every value is Boolean

Some entries are numeric limits, model names or stored strings rather than switches. Confirm the type and current value displayed in the editor before editing. If a supposed flag is missing, there may be a build mismatch, a removed implementation or a name that was collected from code but not exposed to the editor.

Test and roll back deliberately

Record the version, exact flag name and original value, then perform one change. Some settings require restarting the keyboard to reload its configuration; others require a resource or server-side entitlement that a restart cannot provide. The patch project documents backup/restore of settings and flag-store files, but restore support depends on your installed patch.

Frequently asked questions

Does the Atlas toggle flags?

No. It is a static, searchable index. Changes happen inside whatever compatible editor you choose.

Should I enable every attractive feature?

No. Test isolated, reversible changes only when you can observe a specific result.
