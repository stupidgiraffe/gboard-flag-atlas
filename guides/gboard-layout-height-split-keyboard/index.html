Gboard Layout Flags: Keyboard Height, Floating Mode and Split Keys

Compare keyboard size and appearance controls with floating and split layouts without confusing preference flags with geometry models.

What you should know

First use Gboard's built-in settings; layout flags can be limited by screen size, window mode and hardware.

Evidence standard: these are real catalog identifiers, but their effects can be inferred, version-specific, or gated. Check the confidence and APK notes before changing settings.

Standard settings versus experimental layout flags

A theme or keyboard-height setting usually affects appearance or touch targets. enable_adjust_default_keyboard_height and enable_number_row suggest layout preferences, while enable_key_border is visual. A screenshot change does not establish that the underlying tap-correction model was recalibrated; finger position and decoding remain related but separate.

Floating and split are context dependent

enable_auto_float_keyboard_in_landscape and enable_auto_float_keyboard_in_multi_window refer to automatic behavior in certain window states. enable_split_keyboard_on_tablet_large signals a tablet-specific layout condition. Trying to infer support on a small phone from a flag name alone can create misleading reports.

Keep typing tests fair

Compare one-handed and two-handed typing with the same app, device posture and locale. Record screen size, orientation, Android version and whether the UI is floating, split or docked. If the keyboard gets smaller, measure how comfortable and accurate it feels before claiming a particular rendering option makes typing faster.

Frequently asked questions

Does a split-keyboard flag work on every phone?

No. The identifier itself advertises a tablet/large-display condition.

Can smaller keys improve decoding accuracy?

A geometry change alone does not guarantee that; accuracy should be tested separately.
